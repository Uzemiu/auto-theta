# Theta 自动游玩知识库

## 持续目标

用户于 2026-09-22 要求：使用新存档 slot1 不断推进，直到全成就，并同步更新知识库。

本机 Steam 官方成就定义与官方公开列表均包含 28 项。目标覆盖章节、全部关卡、全部星星、机制事件与结局；不能仅完成主线就报告目标完成。

已观察但尚无完成证据的入口见 [待完成清单](remaining-levels.md)；不能只根据已登记的尝试条目推断全游戏欠关数量。

## 推进与记录

- 同时仅一个 agent 操作游戏；其余 agent 只能进行独立分析、文档核验或成就只读检查。
- 通过正常游戏输入推进。不得改写存档进度、注入解锁成就、跳过条件或修改游戏规则来宣称成功。
- 用户于2026-09-23明确禁止使用提示功能：从此指令起，所有agent不得使用“获得启示”、提示按钮或进入简化提示关。通过观察、实验和自主推理解题；正常流程中的必经剧情与机制教学不属于主动索取提示。此约束必须随每次交接传递。此前实际使用过的提示记录保留，不将历史游玩改称全程无提示。
- 每次创建、恢复或委派子 agent 时，必须在任务指令中明确重申禁用提示；子 agent 再次委派时同样传递。已向当前可联系的 chapter1_second_half、chapter2_finish、chapter2_world 重申此命令。
- 可以用实时已观测地图建立搜索模型；模型规则必须由实际操作或游戏教学支持，解法要在实际游戏中验证。
- 每完成一关便保存解法和完成证据、更新进度；每验证机制便更新机制文件。
- 未公开的关卡解法不通过外部攻略或游戏解法代码获取。成就名称与条件只用于验收清单。
- 遇到操作超时先重新观察；遇到预测失配先保留现场证据，再修正模型或撤销，不盲目重放整个序列。
- 到章节节点时汇报一次位置、已完成关卡、未解目标和知识库变更，随后继续下一阶段。

## 成就核验

只读命令：

```powershell
& 'D:\python14\python.exe' tools/read-achievements.py --update
```

此脚本读取当前登录 Steam 账户对应的本地成就缓存与官方 schema，仅写入项目 `knowledge/achievements.json` 和 `artifacts/achievements/`，不修改 Steam 或游戏数据。

账户在本轮早期检查时已有 5 项历史成就，不能把它们计作 GPT 在 slot1 新达成。`account_status` 表示 Steam 本地缓存，`slot1_status` 表示本轮证据，两者应分开核验。缓存同步时间也要保留；最终应确认账户 28/28，并核验 slot1 的相关条件。

## 中断后续接

先确认 agent 是否仍在控制游戏，避免双重输入。然后读取本轮进度、最近证据，并重新观察实时场景。旧位置记录仅用于定位，不能取代实时观察。整体目标未达到时继续推进，不因一个子阶段完成就标记全任务完成。

## 进度交叉核验

```powershell
& 'D:\python14\python.exe' -X utf8 tools/audit-knowledge.py
```

脚本只读 slot1 与知识库，检查本轮每个已完成关卡的解法文件、匹配关卡 ID 的实际完成回执、存档通关操作记录，以及已知动作编码是否一致。审计结果保存到 `artifacts/knowledge-audits/`。它只证明已记录条目的证据一致性，不证明所有关卡或所有成就已经完成；游戏运行时的文件可能继续变化。

动作编码已实测确认 W/A/S/D/X 对应 1/2/3/4/5，2-1 的 TAB 切换在 instructions 中为 T、存档中为 8。审计遇到未支持的动作会报告问题，不静默跳过整关动作记录核验。

组合通关按游戏实际记账：例如 1-X+1-Y 使 dawn、dusk 两个状态完成，计数增加2，但只有 dawn+dusk 一条动作记录，运行时 ID 为 template1。两个关卡条目共享组合解法与证据，并明确保存 component_ids、combined_level、runtime_level_id、save_record_key；不另加一个组合关卡到完成总数，也不声称独立通关。审计同时核对组合标题、各组成关卡状态和合并存档记录。
